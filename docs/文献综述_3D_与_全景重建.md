## 文献综述：三维与全景重建（3D / 360 Reconstruction）与世界模型

### 1. 问题背景与目标

三维与全景重建（3D / 360 Reconstruction）关注的是：**从多视角图像或视频中恢复世界的几何结构与全景语义**，典型输入包括：

- 常规多视角相机拍摄的数据集（如 Mip-NeRF 360、LLFF 等）；
- 360° 全景相机（equirectangular）采集的视频或图像序列；
- 甚至带深度/IMU 的设备（手机 LiDAR、RGB-D 相机、AR 眼镜等）。

在“世界模型（World Model）”视角下，我们希望的不只是离线重建一个静态场景，而是：

- 构建一个**可查询、可渲染、可推理**的空间表示（世界记忆）；
- 支持**多模态输入**（图像、文本、轨迹等）和**多任务输出**（导航、编辑、理解、生成）；
- 面向 **虚实融合（AR/VR）**、**机器人导航** 与 **3D 生成** 等下游应用。

本仓库 `3D_Reconstruction_ing` 的定位是：  
> **围绕 Mip-NeRF 360 等真实世界数据，搭建从 COLMAP → Nerfstudio → 3DGS / 4DGS 的动手实践与技术验证管线，为“世界模型”的 3D / 360 表示打基础。**

---

### 2. 技术路径总览

可以把 3D / 360 重建看成三层技术栈：

1. **几何层（Geometry / SfM / MVS）**
   - 代表：COLMAP、OpenMVG、OpenMVS 等；
   - 目标：从多视角图像估计**相机位姿 + 稀疏/稠密点云**；
   - 本仓库中通过：
     - `COLMAP_与_Nerfstudio_教程.md` 中的 COLMAP 部分与 Mip-NeRF 360 实例，系统走通这一层。

2. **辐射场 / 体渲染层（NeRF & Variants）**
   - 代表：NeRF、Mip-NeRF / Mip-NeRF 360、Instant-NGP、Nerfacto 等；
   - 目标：学习一个**连续体积场**，显式或隐式编码颜色和密度，可从任意视角渲染；
   - 本仓库中通过：
     - Nerfstudio 的 `ns-process-data` + `ns-train` + `ns-render`，对 Mip-NeRF 360 场景进行 NeRF 训练与可视化。

3. **显式高效表示层（3DGS / 4DGS / 其他）**
   - 代表：3D Gaussian Splatting（3DGS）、4DGS（时变高斯）、神经点云等；
   - 目标：用**高斯云 / 点云等显式结构**替代“纯体渲染”，在保证质量的同时显著提升渲染速度；
   - 与世界模型的关系：
     - 更适合实时渲染、编辑和物理交互；
     - 更易与图结构、拓扑等高层语义结合。

在世界模型场景中，这三层通常是叠加使用的：  
**几何层保证物理一致性 → 辐射场层保证真实感 → 显式层保证效率与可编辑性。**

---

### 3. COLMAP + Nerfstudio：从几何到辐射场

本仓库现有的 `COLMAP_与_Nerfstudio_教程.md`（第 1–7 节）已经搭建了：

- 从 Mip-NeRF 360 场景的 `images/` 出发；
- 通过 COLMAP 获得 **SfM 几何结果**（相机位姿、点云）；
- 再用 Nerfstudio 的 `ns-process-data` 将这些结果转化为 `transforms.json` 等 NeRF 训练格式；
- 最终用 `ns-train` / `ns-render` 训练并渲染 NeRF。

这条链路可以概括为：

```text
原始多视角图像
    └─ COLMAP (SfM/MVS)
         └─ 相机位姿 + 点云（几何层）
              └─ Nerfstudio / NeRF (nerfacto 等)
                   └─ 连续辐射场（体渲染层）
                        └─ 渲染/编辑/导出用于下游应用
```

在此基础上，项目后续可以自然延展到：

- 将 Nerfstudio 的 NeRF 结果转换为 3DGS 表示（例如通过 `gsplat` 或相关工具包）；
- 在统一接口下管理 **COLMAP 模型、NeRF 模型、高斯云模型**，为“世界记忆库”打底。

---

### 4. 3DGS / 4DGS 与世界模型

**3D Gaussian Splatting（3DGS）**：

- 用一组带有位置、各向异性协方差、颜色、密度等属性的高斯体元，来近似整个场景；
- 通过 rasterization / splatting 实现**高帧率渲染**，在 3D 浏览、VR 和游戏场景中具有巨大优势；
- 常见工作流：
  - 使用 SfM（如 COLMAP）获得初始相机位姿与粗稀疏点云；
  - 用优化方法拟合高斯参数，使渲染结果逼近输入图像；
  - 支持编辑（删除 / 移动 / 着色高斯）以及风格迁移等扩展操作。

**4D Gaussian Splatting（4DGS）**：

- 在 3DGS 的基础上，把时间或隐空间也纳入参数（比如点的位置/形状/颜色随时间变化），以支持动态场景；
- 更贴近“世界模型”的需求：不仅表示**空间**，还要表示**时间与状态演化**。

对世界模型而言，3DGS / 4DGS 有几个关键优势：

- **显式且紧凑**：相较于隐式 MLP，更利于检索与局部编辑；
- **高效渲染**：适合实时交互、在线规划与闭环控制；
- **容易与语义对齐**：可以在高斯上附加语义标签、实例 ID、材质属性等。

本仓库后续可以围绕以下方向扩展：

- 在 `worldrecon` 环境中加入 3DGS / 4DGS 相关工具（如 `gsplat` 已经在依赖中）；
- 为同一场景维护多种表示：
  - `colmap/`：几何；
  - `nerfstudio/`：NeRF；
  - `gaussians/`：3DGS / 4DGS；
- 统一一个“世界模型描述文件”，记录这些表示之间的映射关系。

### 5. 本仓库结构建议与路线图

结合上述技术路径，本仓库的推荐结构如下（逻辑视图）：

```text
3D_Reconstruction_ing/
├── README.md                 # 项目简介与总体目标（3D/360 + 世界模型）
├── requirements.txt          # 最小 Python 依赖（如 pycolmap）
├── env/
│   └── worldrecon.yml        # Nerfstudio + 3DGS 等完整环境
├── docs/
│   ├── 文献综述_3D_与_全景重建.md      # 你正在阅读的概览与技术路径
│   └── COLMAP_与_Nerfstudio_教程.md   # 从 COLMAP 到 Nerfstudio 的完整实践教程
├── mipnerf360/               # 示例数据（如 db/drjohnson 等场景）
│   └── ...                   # 不建议提交完整数据集，可保留少量示例或使用 .gitignore 控制
└── src/（后续）
    ├── pipelines/            # 封装 COLMAP / Nerfstudio / 3DGS 的 Python 管线
    ├── viz/                  # 可视化工具
    └── world_model/          # 统一的世界表示接口与实验代码
```

**路线图简述：**

1. **第一阶段：几何 + NeRF 打通**（本仓库目前已基本完成）
   - Mip-NeRF 360 + COLMAP + Nerfstudio，从 `images/` 一路走到可视化渲染。
2. **第二阶段：加入 3DGS / 4DGS 与显式表示**
   - 在 `worldrecon` 环境里引入 3DGS 训练与渲染脚本；
   - 针对同一场景，比较 NeRF 与 3DGS 的质量和速度。
3. **第三阶段：走向“世界模型”**
   - 设计统一的数据结构来管理“世界多种表示 + 语义标签”；
   - 探索从文本/行为到 3D / 4D 世界编辑与生成的接口。

这份文档旨在为后续实验和代码组织提供一个清晰的“技术地图”，让 `3D_Reconstruction_ing` 不仅是 COLMAP / Nerfstudio 的练习项目，更是通往世界模型 3D 表示的一条实践路线。
